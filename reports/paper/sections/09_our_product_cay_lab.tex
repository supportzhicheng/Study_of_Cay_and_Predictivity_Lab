\section{Our Product: CAY Lab}
\label{sec:our_product_cay_lab}

The next stage of this project is to package the replication and extension
workflow into a user-facing CAY Lab. The objective is to keep the empirical
pipeline transparent while allowing users to run customized predictivity
studies without rewriting analysis code.

\subsection{Product Scope}

CAY Lab is designed around four user-controlled functions:
\begin{enumerate}
  \item \textbf{Choose the CAY variant.} Users can select the decomposition
  family they want to analyze (\texttt{house\_wealth},
  \texttt{region\_proxy}, or \texttt{wealth\_groups}). The required CSV inputs
  are generated locally under \texttt{cay\_data/} using user-provided
  credentials and are not bundled as real datasets in version control.

  \item \textbf{Choose the training window.} Users can set the estimation
  window (sample range / rolling training length) to match their preferred
  historical regime.

  \item \textbf{Choose the predictive horizon.} Users can select whether CAY is
  evaluated for near-term or medium-term predictivity (for example 1-quarter,
  4-quarter, or 8-quarter horizons).

  \item \textbf{Choose the risky asset target.} Users can specify a ticker
  (for example \texttt{QQQ}) and CAY Lab forecasts that asset's forward
  return.
\end{enumerate}

\subsection{Interpretation and Reproducibility}

These controls are intended to change \emph{inputs and horizons}, not to change
core econometric definitions silently. Every run should preserve explicit sample
metadata, selected options, and generated artifacts so users can compare
results across CAY definitions and risky-asset targets in a reproducible way.

\subsection{Official CAY Lab Runtime Interface}

The \texttt{doit} interface exposes the four product controls directly:
\begin{itemize}
  \item \textbf{Input range:} \texttt{--input-start}, \texttt{--input-end}
  \item \textbf{Prediction period:} \texttt{--prediction-period}
  \item \textbf{Decomposed CAY choice:} \texttt{--cay-decomposition}
  \item \textbf{Risky asset ticker:} \texttt{--risky-ticker} (or
  \texttt{--risky-tickers} for a comma-separated list)
\end{itemize}

Example invocation:
\begin{verbatim}
doit -f cay_lab/dodo.py chartbook \
  --cay-decomposition house_wealth_groups \
  --input-start 2023Q1 \
  --input-end 2026Q1 \
  --prediction-period 2 \
  --train-periods 8 \
  --risky-ticker QQQ
\end{verbatim}

For policy compliance, real decomposition datasets are not committed to the
repository. Users must generate local \texttt{cay\_data/*.csv} files with their
own credentials before running this command.

\subsection{Worked Example (Wealth Groups, 2-Quarter QQQ Horizon)}

To demonstrate the product workflow, we ran CAY Lab with:
\begin{itemize}
  \item dataset: \texttt{cay\_components\_wealth\_groups\_q.csv},
  \item requested sample range: 2023Q1--2026Q2,
  \item predictive window: 2 quarters,
  \item risky asset ticker: \texttt{QQQ}.
\end{itemize}

Because the latest available quarter in the current wealth-group source is
2026Q1, the effective upper bound is 2026Q1. After predictor construction, the
usable input panel runs 2023Q2--2026Q1. Because the target is a realized
2-quarter-ahead QQQ return, the last quarter with an observable realized target
in this run is 2025Q3, so the evaluated forecasting sample is 2023Q2--2025Q3.
For rolling diagnostics, we use an 8-quarter training window so in-sample
$R^2$ is not mechanically one (a 4-quarter window with three predictors plus
intercept is exactly identified and can force perfect in-sample fit).
The generated artifacts include:
\begin{itemize}
  \item \texttt{subcay\_predictivity\_prepared.csv},
  \item \texttt{subcay\_predictivity\_tests.csv},
  \item \texttt{subcay\_predictivity\_rolling.csv},
  \item \texttt{chartbook\_subcay\_predictivity.pdf}.
\end{itemize}
